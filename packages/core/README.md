# @game-hub/core

Game-Hub 通用核心包，负责模块装配、标准事件与命令路由、系统管理员鉴权，以及 Vault 提供的持久化接口。渠道连接、平台 API 和插件业务不在核心中实现。

## 系统管理员注册与权限

系统管理员注册令牌由本包定义和校验，任何渠道共用同一套系统认证流程；渠道自己的连接令牌由对应渠道包说明。

| 变量 | 用途 | 未配置时 |
| --- | --- | --- |
| `GAMEHUB_ADMIN_REGISTRATION_TOKEN` | 系统管理员注册令牌，仅由核心验证 | 关闭令牌注册，已有授权保留 |
| `GAMEHUB_ADMIN_USERS` | 可选的环境预置管理员，完整“平台:用户ID”以逗号分隔 | 无环境预置身份，仍可用注册令牌认证 |

首选入口是聊天注册，不要求用户预先填写个人 ID。维护者在实际部署用私有 `.env` 中设置 `GAMEHUB_ADMIN_REGISTRATION_TOKEN`，由部署环境传入 Game-Hub；根 `.env.example` 仅汇总变量，真实值不能写入模板或仓库。直接运行 Node 时由启动环境传入变量，`npm start` 本身不加载 `.env`。注册令牌不含空白，留空关闭注册，没有默认令牌或渠道连接令牌回退。

### 认证、授权和撤销

用户在任一已接入渠道私聊机器人，发送系统当前调用标记下的 `认证 <注册令牌>`。渠道适配平台事件及发送者身份，核心校验后只为发送该指令的本人授权，不接受在认证参数中指定另一个用户。群聊注册、错误令牌、缺失令牌或不完整身份均不授予权限。

身份使用完整的 `platform:user-id`，如 `telegram:<数字用户ID>`、`qq-napcat:<QQ号>`；同数字 ID 不跨平台互认，也不自动继承群主或群管理员权限。系统管理员能管理同一 Game-Hub 实例的全局功能，不能将其误认为仅管理当前渠道。

成功注册的身份保存在 Vault 的 `system:admin_users`，重启后保留，重复注册不会重复写入。注册令牌自身不入库，认证命令无论成败都由系统路由消费，不进入普通聊天或 AI 上下文。权限名单写入失败时，内存权限保持原状。

已有系统管理员可使用系统当前调用标记下的以下指令：

- `管理员列表`：显示完整身份和“环境预置／已注册”来源。
- `添加管理 <平台:用户ID>`：为其他完整平台身份授权，不接受裸 ID、昵称或用户名。
- `移除管理 <平台:用户ID>`：撤销聊天注册的授权，立即生效且重启后保持撤销。

环境预置身份不是聊天注册的必填项，也不能通过聊天指令撤销；维护者需从 `GAMEHUB_ADMIN_USERS` 中移除并重新载入容器环境，避免“指令撤销后重启又恢复”。注册身份与预置来源分开保存。

注册令牌可重复使用；轮换只影响后续注册，不自动撤销已有管理员。撤销授权与轮换令牌是独立操作，仍持有有效注册令牌的人可以重新认证。

### 升级与部署

渠道连接令牌、旧 `GAMEHUB_TOKEN` 或 `ACCESS_TOKEN` 均不能用于注册系统管理员，旧 `MASTER_QQ` 回退也不再使用。已有完整平台身份授权保留；旧存储中的裸 ID 停止赋权并输出迁移提示，但启动时不猜测其平台、不改写原数据。用户可重新认证，或由管理员按完整身份重新授权。环境预置名单若含裸 ID 则启动报错，必须改成完整平台身份。

根 Compose 已映射系统注册令牌和可选预置名单。若实际使用仓库外的 Compose，需在对应部署文件中添加同名环境映射；修改 `.env` 后重建 Game-Hub 才会载入新值，单纯 restart 不会更新环境。

部署前备份 Vault。本权限整理不引入数据库结构迁移。通用操作见[部署说明](../../docs/operations.md)；Telegram 机器人凭据见[Telegram 包](../channel/telegram/README.md#渠道环境变量)，NapCat 连接令牌见[NapCat 包](../channel/napcat/README.md#napcat-连接-game-hub-的令牌)，独立 AI 管理权限见[插件包说明](../plugin/chat-ai/README.md#ai-插件管理员注册令牌)。
