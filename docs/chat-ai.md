# chatAi 使用说明

更新：2026-10-27。插件 ID 为 `chat-ai`，模型 provider 为 `llm`。示例使用当前默认前缀 `!`；实际回复中的可执行命令由总线按当前命名空间生成。

## 指令帮助

`!帮助` 只列常用操作；`!帮助 <指令>` 查看参数、示例与作用范围；`!帮助 全部 [页码]` 查看完整清单。每项功能仅保留一个名称，详见 [统一指令说明](commands.md)。

## 最短使用路径

运行环境提供 `CHATAI_KEY_MAIN`。需要独立 AI 管理员认证时另提供 `CHATAI_ADMIN_TOKEN`；系统管理员天然具有 AI 管理权限。密钥仍由维护者放入环境，本轮不实现环境文件托管或密钥修改指令。

1. 管理员私聊发送 `!设置` 查看当前状态。
2. `!连接新增`：按向导填写显示名称、OpenAI 兼容 base URL、密钥环境变量名。地址示例为 `https://api.example.com/v1`，不要照抄成实际服务。
3. `!发现模型 <连接ID>`，回复当前列表编号，然后给模型起显示名称，例如“日常聊天”。服务没有标准 `/models` 时，用 `!模型新增 <连接名称或ID>` 手动填写上游模型 ID。
4. 回复“确认并使用”，模型立即用于当前私聊；也可先保存，再 `!模型列表` 回复编号选择。
5. 需要其它会话跟随此模型时，用 `!默认模型 <名称或ID>`。进入目标群执行 `!模型切换 跟随默认`；群默认只在 @机器人时回复，`!策略设置 all` 可改为每条普通文本回复。
6. 私聊发送 `!人物导入` 并单独发送自己的卡片文件，再用 `!人物列表` 选择或 `!人物切换 <人物ID>` 启用。

已有旧版 `main` 档案会自动关联一个服务连接，保留原 ID、模型、密钥引用及参数，不需要重填。可以 `!模型命名 main 日常聊天` 改显示名称，再 `!模型切换 日常聊天` 立即应用。模型新增统一使用已有服务连接；原四步向导已移除，已有模型 ID 和配置保留。

编号只对应当前用户、机器人和本次列表，10分钟过期；不是长期模型 ID。重名名称无法唯一匹配时，请用稳定 ID 或重新打开列表选择。长模型列表按页展示，每页编号从1开始。

## 服务、模型和作用域

一个服务连接包含名称、base URL 和密钥引用，可以有多个模型。同一 URL 配不同密钥是不同连接，不自动混合。连接修改会影响其全部模型并使相关旧请求失效；仍有关联模型的连接不能删除。`!模型修改 <名称或ID>` 只修改单个模型的上游模型 ID，不再修改连接地址或密钥引用。

模型包含稳定 ID、显示名称、上游模型 ID、连接 ID 和温度/输出/超时/上下文预算参数。会话可以显式选择模型，或跟随全局默认。启动时自动选取默认模型只执行一次；管理员主动设默认或切换会话可以立即生效，不依赖插件代码热重载。新增档案不悄悄改变其它会话。删除模型会解除相关会话绑定，删除默认模型后需明确重设默认。

`!模型详情 [名称或ID]` 展示名称、上游模型、所属连接、地址、实际请求路径、密钥是否存在、关键参数和最近生成结果。地址自动补齐 `/chat/completions`。`!模型参数 <ID> 温度 <0–2>`、`输出 <1–4096>`、`超时 <1000–120000毫秒>`、`上下文 <2000–80000字符>` 可以修改参数。

`!模型检测 [ID]` 和启动健康检查只验证密钥存在性及模型列表端点；HTTP200必须能解析为标准模型列表才显示该层可用，不代表聊天生成已验证。错误日志默认保留，debug仅增加诊断细节。日志不记录正文、人物全文或密钥。最近生成结果在 `!状态` / `!模型详情` 查看。

## 管理指令

除 `!AI认证 <token>`（仅私聊）外，所有命令均限系统管理员或 AI 管理员。普通用户的日常自动聊天受会话策略和额度控制。删除 AI 管理员只允许系统管理员；AI 管理员列表变动不撤销系统管理员权限。

| --- | --- |

| 选择 / 默认 / 检测 | `!模型切换 <名称或ID或跟随默认>`、`!默认模型 <名称或ID>`、`!模型检测 [ID]` |
| 人物维护 | `!人物列表`、`!人物预览 <ID> [页]`、`!人物导入 [文本或JSON]`、`!人物编辑 <ID>`、`!人物覆盖 <ID> [文本或JSON]`、`!人物导出 <ID>`、`!人物删除 <ID>` |

## 人物卡

插件不附带或自动安装个人角色。管理员通过文件导入自己的卡片；卡片保存在运行数据库中，个人源文件和创作记录不随源码发布。

支持完整 TXT/Markdown 人设、V2/V3 常用字段 JSON 与扁平 JSON。单卡最多1 MiB，设定和世界书正文完整保存，显示名称最多60字；不宣称完整兼容 SillyTavern。支持 `{{char}}` / `{{user}}`、开场白和基础关键词世界书；`{{original}}` 为空，不执行脚本或任意模板代码。文本支持 UTF-8、带 BOM 的 UTF-16。PNG 内嵌人物卡暂不解析。

管理员在私聊发送 `!人物导入`，再单独发送 `.txt`、`.md`、`.markdown` 或 `.json` 文件，也可直接粘贴完整文本。导入窗口10分钟有效，绑定发起人、机器人和私聊；回复“取消”或发送新的管理指令结束旧窗口。导入不自动启用人物，也不进入聊天历史。文件内容只决定角色表达，不能授予搜索、视频解析、QQ收藏或群管理能力。

QQ 文件通常以独立消息或通知到达，渠道负责跨容器下载，插件不读取 NapCat 本地文件路径，也不抓取任意用户 URL。推荐使用支持 Stream API 的 NapCat；旧版本只有在文件接口返回 base64 时可兼容，否则明确提示升级。协议参考：[NapCat 文件传输说明](https://napneko.github.io/develop/file)。

同名导入不会覆盖；`!人物覆盖 <ID>` 后单独发文件可明确覆盖并保持会话绑定。删除指令先报告影响，再要求附加“确认”。编辑是私聊分步交互。`!人物预览 <ID> [页]` 分页查看，`!人物导出 <ID>` 在私聊回传完整 JSON 文件。QQ 说明文字与文件使用两个原生请求依次发送；部分失败会提示，不自动重发已交付部分。普通长文字也按2500字拆分，避免单条消息过长。

不同人物的消息分支分开保留，切回人物可以继续旧分支；通用助手也有独立分支。首次进入空分支会发送卡片开场白。清空上下文只清当前人物分支及其摘要，不清显式长期记忆；删除人物会删除该人物的全部消息分支并解除绑定。

## 可靠性和额度

QQ正文优先从结构化text段提取，@和引用元数据不混入模型正文。已识别指令、未知指令、向导配置、业务已消费消息、凭据和机器人自身消息都不进入聊天回复链。

持久事件收据覆盖回复去重，清空或裁剪历史不会让旧事件再调用模型。每会话FIFO，入队时固定用户上下文边界，不提前包含后续提问；在执行时可加入更早问题的已完成回复。不同会话并行。

清空、切换人物/模型、停用、取消等通过epoch与AbortController阻止旧结果和旧错误继续发送。模型调用前预留每日额度；已经调用但输出失效/交付失败仍计数。tokens在返回后记录，与QQ交付结果分开；连接失败的有界内部重试仍属于同一次逻辑请求。自动提示有冷却，显式管理员指令每次反馈。

上下文使用最近消息窗口和总字符预算（默认12000字符），不是准确token计数。人物与宿主规则最多占总预算60%，其余用于最近对话；超预算仅裁剪此次模型输入，不改变已保存的原卡。`!模型参数 <ID> 上下文 20000` 可按模型调整，`!模型详情` / `!上下文` 显示预算。预算应结合服务实际能力设置。

## 可选行为（默认关闭）

| 能力 | 开启与维护 |
| --- | --- |
| 事件响应 | `!事件设置 on/off` 批量开关模板；`!事件设置 <poke或join或leave或recall> <off或template或persona> [模板]` 逐项设置 |
| 表情 | 私聊 `!表情添加 <短ID> <名称>` 后单独上传图片；也兼容原HTTPS地址写法。`!表情列表 [页]`、`!表情预览 <ID>`、`!表情替换 <ID>`、`!表情删除 <ID>`；目标会话 `!表情设置 on/off` |
| 主动问候 | 当前会话 `!主动设置 <5–1440分钟>`，0关闭，`!主动状态` 查看；按空闲时间触发 |
| 显式长期记忆 | `!记忆添加 <内容>`、`!记忆列表`、`!记忆删除 <编号>`，`!记忆设置 on/off` 控制注入 |
| 摘要 | `!生成摘要` 手动调用模型并保存当前人物分支摘要，`!删除摘要` 清除 |

表情由模型选择已登记ID，执行器只接受文字和已登记表情两种有限动作。支持只发表情，文字与图片各一个气泡；图片每会话冷却30秒，未知ID不执行。上传的 PNG/JPEG/GIF/WebP 最多4 MiB，校验文件头并以 SHA256 去重，图片由本地库保管；远程链接标记为待验证，可能过期。

`!表情标签 happy 开心,微笑 <人物ID>` 设置情绪标签和人物素材集，人物填 `*` 表示通用，标签填 `-` 清空。模型只看到通用和当前人物的素材（最多50个）。`!表情导入` 后发送 JSON 素材包可批量登记，格式为 `{"assets":[{"id":"happy","label":"开心","file":"https://cdn.example.com/happy.png","tags":["开心"],"characterId":""}]}`；file 也可用 `base64://...`。整包最多100项、4 MiB，冲突或无效项整包回滚。不内置第三方图包，管理员提供有权使用的素材。

事件默认关闭。template 使用固定文字，不调用模型；persona 使用当前人物和会话上下文，经同一额度、队列与取消机制生成，并可选择不回复，不伪造用户发言。同类事件同一发起者冷却30秒，会话全部事件共用10秒冷却，突发期间只处理首个。人物卡中的“必须回应”等文字不能覆盖关闭状态和冷却。

主动任务持久化在插件表内，由现有应用进程的生命周期管理，无额外后台进程。23:00–08:00（Asia/Shanghai）保持安静，跳过错过的轮次，不补发积压。每轮外部操作前推进计划，因此为至多一次尝试，交付失败不盲目重放。执行前检查插件状态、会话策略、创建者管理员权限与额度；用户重新发言会使正在生成的旧问候失效。总线或容器关闭时任务不会运行。

长期记忆每会话最多40条、每条最多500字符，仅显式登记，不自动推断个人画像，不跨群/私聊混用；注入还有总长度预算。删除记忆会使旧请求失效。摘要消耗一次同额度模型调用，不自动触发；会合并已有摘要，保留原消息。

平台撤回按会话与平台消息 ID 定位，删除目标消息及使用过该消息的派生回答，失效依赖摘要，并取消依赖原文的排队/进行中回复。其它消息和人物分支保留；未知 ID 不清空历史，早到撤回会阻止原消息迟到入库。索引保留裁剪后的来源关联以处理摘要撤回。此项卫生处理不依赖是否开启事件发言。升级前未记录平台 ID 的旧消息无法精确关联；可手动清空当前人物分支。显式记忆仍需管理员单独删除，不自动接受好友或加群请求。

## 迁移、部署与验收边界

迁移只在装配插件时执行，新增插件自有表与字段，不删除旧模型、连接密钥引用或已有消息。原有历史归入通用助手分支。上线前备份完整数据库；回滚保留新表，不运行破坏性降级SQL。示例和向导中不放真实部署地址。

本轮不实现插件代码热重载、总线托管环境文件、统一插件初始化、向量数据库、语音、自动画像或PNG人物卡解析。已有环境变量值改变仍需维护者按部署方式更新运行环境；命令配置的模型/人物/策略变更不依赖重启。

本地自动化测试使用内存/临时数据库和模拟HTTP；原始OneBot消息、网关消息段和通知另有集成回归。生成接口、QQ图片交付、群通知类型以及人物语气，需要部署后人工验收，不能用模拟测试代替。
